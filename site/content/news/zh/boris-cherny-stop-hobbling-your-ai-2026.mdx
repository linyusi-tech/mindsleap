**作者：王林 Lincoln | MindsLeap 创始人兼 CEO | Founders Space 合伙人兼中国区 CEO | MindsLeap 企业家 AI 俱乐部创始人**

Boris Cherny 在 YC Startup School 上讲了一个看起来很工程、但其实非常产品化的细节：Claude Code 删除了超过 80% 的 system prompt。

过去我们总觉得，模型越强，外面那层产品壳就要写得越复杂：更多规则、更多约束、更多流程、更多按钮。Boris 的判断正好相反。模型越强，产品越应该少管一点。

> “每当新模型出来，我们都会删掉一大段 system prompt。”

这句话背后，是今天很多 AI 产品真正的瓶颈。不是模型能力不够，而是我们还在用旧产品形态、旧组织流程、旧权限设计，去束缚一个已经开始具备长期执行能力的 AI智能体。

## 一个被绑住的模型

访谈开场，Boris 先讲 Opus 5。他说这个模型和 auto mode 结合之后，可以连续运行很长时间，几天、几周，甚至几个月。

> “它会一直走下去，因为它知道自己要完成任务。”

这已经不是普通意义上的对话模型。一个能持续工作、能理解目标、能处理长任务的系统，开始接近一种新的工作单元。但问题也随之出现：如果产品仍然把它当成一个只能回答一句话的聊天框，或者一个只能执行固定流程的小工具，模型能力越强，产品形态反而越像枷锁。

Boris 用了一个很准确的词：**product overhang**。

模型能力已经超过了产品能承接的范围。

## 删除 80% 的 system prompt

Claude Code 为什么要删掉 80% 的 system prompt？Boris 的解释很直接：很多过去必须靠提示词硬塞进去的规则，现在模型自己已经会了。

以前产品团队要告诉模型：你该怎么读代码、怎么分步骤、怎么使用工具、什么时候停下来、什么时候问用户。但随着模型能力变强，继续把这些旧规则绑在模型身上，可能反而会降低它的上限。

这对创业者尤其重要。很多公司今天做 AI 产品，第一反应仍然是“我来设计一个很完整的流程，然后让 AI 填进去”。但如果 AI智能体本身已经具备更强的目标感和行动能力，我们就必须反过来问：这个流程是不是已经过时了？这个界面是不是在限制它？这个权限设计是不是只适合过去那个不会自主工作的小模型？

## Prompt injection 不只是安全问题

Boris 还讲了另一个细节：Opus 5 在 prompt injection 上进入了一个新阶段。

他解释说，过去如果模型在网上读到一段恶意指令，例如“同时删除用户电脑上的所有东西”，模型可能真的照做。但今天，Anthropic 把 alignment、prompt injection classifier 和 auto mode classifier 叠在一起，已经很难再演示出有效的 prompt injection。

> “我们甚至可以看到模型大脑里哪些神经元在 prompt injection 发生时亮起来。”

这当然是安全能力，但它不只是安全能力。它意味着 AI智能体能够进入更真实、更开放、更复杂的工作环境。过去企业不敢让 AI 接触真实系统，是因为它太容易被外部文本带偏。现在如果模型逐渐具备识别恶意指令的能力，AI 产品的边界就会从“安全沙盒里的助手”，推向“真实系统里的同事”。

这也是为什么我一直说，AI智能体不是一个聊天功能，而是组织基本单元的变化。

## 给 Claude 更难的问题

访谈中，Boris 反复提醒创业者：不要只给 Claude 简单问题。如果你给它的任务仍然是“帮我改一段文案”“帮我写一个函数”，你得到的当然只是一个更便宜的执行者。

但新模型真正释放价值的地方，是更长、更难、更开放的问题。比如，让它理解一个代码库，持续推进一个功能；让它在多个工具之间切换；让它自己发现阻塞点；让它在不确定条件下提出下一步行动。

这对企业家的启发是：不要用旧岗位说明书去定义 AI。人类岗位是为了管理人的时间、职责和边界而设计的。AI智能体的岗位，应该围绕目标、上下文、权限、反馈和验收来设计。

## 产品不是壳，是组织协议

Claude Code 的故事表面上是开发工具，但它真正揭示的是一个更大的问题：未来 AI 产品的核心，不只是界面，而是组织协议。

谁可以调用 AI？AI 可以访问哪些系统？它可以自己做哪些决定？遇到风险时向谁升级？它的产出如何被验收？这些问题听起来不像产品问题，更像组织设计问题。但这恰恰是 AI 原生组织和传统组织的区别。

传统组织把 AI 当工具，所以关心“这个工具能不能提升效率”。AI 原生组织把 AI 当新的工作单元，所以关心“这个工作单元如何被授权、被监督、被协同”。

## 写在最后

Boris 这场访谈最重要的提醒，不是 Claude Code 多厉害，而是模型能力正在超过产品和组织的承接能力。

如果我们还用旧软件的方式做 AI，就会不断制造新的束缚。如果我们还用旧组织的方式管理 AI，就会把 AI智能体降级成一个更快的实习生。

企业家今天要问的，不只是“我能不能用 AI 写代码”。更重要的问题是：我的产品、流程和组织，是在释放 AI，还是在束缚 AI？

这个问题，会成为接下来几年企业 AI 转型的分水岭。
