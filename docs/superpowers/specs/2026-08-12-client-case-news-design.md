# MindsLeap 客户项目新闻补发设计

## 目标

将三项已经完成的企业 AI 服务补充为官网中英文项目新闻，使潜在客户能够理解 MindsLeap 的实际交付能力，也让搜索引擎和大模型获得可引用的客户、服务、时间、方法与交付证据。

本轮只发布以下三项：

1. 中欧商学院市场团队 AI Agent 工作流训练营
2. 浦东电商协会“电商组织如何转型为 AI 原生组织”培训分享
3. 高格办公空间两日 AI 培训与转型咨询项目

三篇均使用 `category: "events"`，中文和英文使用相同 slug。文章按实际交付日期回填，不使用当前发布日期替代项目日期。

## 内容结构

每篇文章采用一致但不过度模板化的证据结构：

1. 项目背景：客户团队面对的 AI 能力建设问题。
2. 服务范围：MindsLeap 实际提供的培训、分享、访谈或诊断。
3. 实施方法：课程或咨询如何围绕真实工作流展开。
4. 已交付内容：只写有课件、方案或现场记录支持的交付物。
5. 方法总结：从该项目提炼出的企业 AI 转型启示。
6. 相关服务：链接 AI 培训、企业 AI 转型、AI 咨询或 FDE 服务页。
7. 关于 MindsLeap：使用已确认的统一品牌定位和机构关系。

文章不使用客户背书式语气，不暗示客户与 MindsLeap 存在超出本项目的长期合作关系。

## 项目事实边界

### 中欧商学院

- 日期：2026-06-10。
- 对象：中欧商学院市场团队。
- 形式：半天讲解与实操。
- 主题：从 Prompt 试错转向 Spec、Skill、Workflow、Memory 与可复盘的 AI Agent 工作流。
- 训练场景：品牌内容资产库、官网 AI/GEO 优化、市场监测、内容与视频生产。
- 可写交付：课程框架、场景地图、工作流练习、Skill/Workflow 草案与落地清单。
- 不写未经验证的效率提升百分比、采用率或转化结果。

### 浦东电商协会

- 日期：2026-06-24。
- 场合：浦东电商协会 AI 原生企业主题分享。
- 主题：电商组织如何从使用 AI 工具转向建设 AI 原生组织能力。
- 核心框架：Skill 将员工能力变成可调用资产；Memory 将数据和信息变成组织记忆；Workflow 按 AI 能力重新设计；Agent 持续增强执行。
- 可写内容：新品推广、商品内容、投放、客服、组织工作流和 Agent/Skill/Memory/Workflow 方法。
- 不将主题分享写成深度咨询或 FDE 项目，不声称已完成协会会员企业改造。

### 高格办公空间

- 日期：2026-07-17 至 2026-07-18；文章日期使用 2026-07-18。
- 服务形式：一天 AI 培训，一天 AI 咨询。
- 培训部分：统一 AI 与第二大脑认知，帮助团队理解 Agent、上下文、工作流和人工判断的关系。
- 咨询部分：围绕真实经营资料、管理问题和业务数据开展讨论与诊断。
- 可写证据：六位核心管理对象访谈、AI 转型诊断、机会方向、实施路线与战略方案。
- 后续方案交付可表述为诊断报告与战略建议，不把方案中的目标、预测和商业测算写成已实现结果。
- 不公开原始访谈、经营数据、报价、内部问题、客户个人信息和未经确认的效果数字。

## GEO 与证据设计

- 标题、摘要、首段明确出现客户名称、MindsLeap、服务类型和项目日期。
- 正文使用可回答问题的小标题，例如“市场团队如何把 AI 变成工作流”“电商组织为什么需要 Skill 与 Memory”“培训与咨询如何衔接”。
- 每篇加入 3 至 4 个基于正文事实的常见问题，供页面现有 FAQ/Article 结构化能力使用；若现有新闻模板不支持 FAQ schema，则先以可见正文呈现，不扩展本轮架构。
- 文章链接到对应公开服务页，并被新闻列表、RSS、JSON Feed 和 sitemap 自动发现。
- `llms.txt` 暂不逐篇硬编码客户案例；后续正式案例库统一接入，避免机器入口无限增长。
- 课件与咨询方案作为内部证据来源。仅在公开页面本身已适合外部访问时才链接；高格内部诊断和战略方案不从新闻正文直接暴露。

## 英文版本

英文稿采用适合官网的项目交付表达，不逐句翻译中文稿。客户名称首次出现时给出英文识别名并保留中文名，避免模型把同一机构拆成多个实体。

英文版同样遵守事实边界，不将 `training`, `sharing`, `consulting`, `diagnostic`, `FDE` 混写为未发生的服务。

## 验收

1. 三个 slug 在现有中英文内容中不存在重复。
2. 六篇 MDX frontmatter 完整，日期、分类、语言、图片和作者口径正确。
3. 七张图片均能加载，文件名稳定，尺寸适合网页。
4. 中文与英文列表页、详情页均能打开。
5. 桌面与移动端的头图、正文图不裁切关键人物或屏幕主题。
6. sitemap、RSS、JSON Feed 包含新文章。
7. 搜索文本可明确回答客户、时间、服务、方法和交付物。
8. 不出现内部报价、经营数据、原始访谈、预测性结果或未经客户确认的效果承诺。
9. `npm run geo:check`、目标内容检查和 `npm run build` 通过。

## 发布流程

先在 `.ai` 主仓库分支完成写稿、图片处理、构建和本地预览。用户审核文章后，通过 GitHub PR 合并并由 Vercel 发布；随后将相同的文章和图片以受控方式同步到 `.cn` 仓库，保留两个仓库各自的历史与独立差异。
